## 1. Context & Objectives

Milestone M8 (Production Operations) continues with WP-8.2: **DPDP operations**.
As autonomous AI agents process customer profiles, contact details, interaction histories, and clinical appointments, compliance with India's **Digital Personal Data Protection Act, 2023 (DPDP Act 2023)** is a strict legal and operational prerequisite for enterprise go-live.

Core objectives for 100% production-level implementation:
1. **Purpose-Bound Consent Ledger (§6, §7):** Affirmative, versioned notice tracking with deterministic SHA-256 notice hashes, multilingual language tracking (`en`, `hi`, `te`, `ta`, etc.), effortless withdrawal handling, and Ed25519-signed proof receipts via `ProofService`.
2. **Data Principal Rights & SAR Lifecycle (§11–§14):**
   - §11: Right to Access (data portability package export via `Customer360Service.exportCustomerData()`).
   - §12: Right to Correction (attribute updating with audit records).
   - §12: Right to Erasure / Right to be Forgotten (two-phase erasure: profile anonymization + irreversible SHA-256 tombstone digest + Ed25519 proof receipt).
   - §13: Right of Grievance Redressal (enforcing statutory 72-hour SLA).
   - §14: Right to Nominate (proxy authorization registration).
3. **Automated Data Retention & Purge Engine (§8(7)):** Purpose fulfillment enforcement, automated cutoff date calculation, scanned vs purged counts, support for both `anonymize` and `hard_delete` actions, and signed proof receipts.
4. **DPBI Breach Notification Engine (§8(6)):** Data Protection Board of India regulatory intimation packages, DPBI reference identifier generation (`DPBI-YYYY-XXXXXXXX`), affected principal notification templates, and operational runbook.
5. **Fastify REST APIs:** 14 secure endpoints under `/api/v1/dpdp/*` with JWT authentication, RBAC permissions, and strict `TenantContextManager` isolation.
6. **Documentation & ADR:** `DPDP_COMPLIANCE_MANUAL.md`, `DPDP_BREACH_NOTIFICATION_RUNBOOK.md`, `ADR-029-dpdp-operations-and-consent-ledger.md`.
7. **Verification Evidence:** `tsc --noEmit` exiting code 0, 100% passing tests in `tests/unit/dpdpOperationsProduction.test.ts`, 0 files touched under `web/`.

## 2. Changes Implemented

### A. Database Migration 054 (`src/storage/migrations/054_dpdp_operations_schema.sql`)
- Created 4 dedicated tables with multi-tenant scoping and foreign keys:
  1. `dpdp_consent_ledger`: Tracks purpose-bound consent (`status`: `granted`, `withdrawn`, `expired`, `superseded`), `notice_version`, `notice_hash`, `language`, `valid_until`, `proof_receipt_id`, and withdrawal metadata.
  2. `dpdp_rights_requests`: Tracks Data Principal SAR requests (`request_type`: `access`, `correction`, `erasure`, `grievance`, `nominee`), `sla_expires_at`, `payload_json`, `erasure_tombstone_hash`, `proof_receipt_id`, and completion timestamps.
  3. `dpdp_retention_jobs`: Tracks automated purge executions, target resource classification, retention days, cutoff timestamps, scanned and purged counts, and proof receipts.
  4. `dpdp_breach_incidents`: Tracks breach incidents, severity (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`), breach types, DPBI reference numbers, intimation timestamps, DPO contact, and principal notifications.

### B. Domain Models & Schemas (`src/dpdp/types/dpdpTypes.ts`)
- Defined Zod schemas and TypeScript interfaces using `z.input<...>` for ergonomic caller inputs and `z.infer<...>` for validated runtime representations.
- Schemas: `GrantConsentInputSchema`, `WithdrawConsentInputSchema`, `SubmitRightsRequestInputSchema`, `ExecuteRightsRequestInputSchema`, `ExecuteRetentionJobInputSchema`, `ReportBreachIncidentInputSchema`.
- Models: `DpbiNotificationPackage`, `DpdpConsentRecord`, `DpdpRightsRequestRecord`, `DpdpRetentionJobRecord`, `DpdpBreachIncidentRecord`.

### C. Repository Layer (`src/dpdp/repositories/dpdpRepository.ts`)
- Implemented `DpdpRepository` with tenant boundary assertion via `TenantContextManager.getTenantId()`.
- Provides atomic query and mutation methods for consent grants, superseding prior active consents, withdrawal status updates, SAR tracking, retention job recording, and breach incident management.

### D. Compliance Service Engine (`src/dpdp/service/dpdpService.ts`)
- Implemented `DpdpService` integrating with `ProofService`, `Customer360Service`, `CustomerRepository`, `ConsentRepository`, and `auditLogger`:
  - `grantConsent`: Computes SHA-256 notice hash, supersedes prior active consent, issues Ed25519 receipt (`actionType: 'dpdp.consent.grant'`), syncs to Customer 360 consent table.
  - `withdrawConsent`: Affirms withdrawal, marks ledger `withdrawn`, revokes active permissions, issues Ed25519 receipt (`actionType: 'dpdp.consent.withdraw'`).
  - `submitRightsRequest`: Calculates statutory SLA (72 hours for grievance, 168 hours for access/correction/erasure/nominee).
  - `executeRightsRequest`:
    - `access`: Exports `CustomerExportPackage` with cryptographic access receipt.
    - `erasure`: Anonymizes customer PII, unlinks identities and timeline events, computes irreversible SHA-256 tombstone digest, issues Ed25519 receipt (`actionType: 'dpdp.data_principal.erasure'`).
    - `correction`: Updates profile attributes with proof receipt.
    - `grievance`: Adjudicates complaint and issues resolution receipt.
    - `nominee`: Registers proxy credentials and issues receipt.
  - `runRetentionPurge`: Derives cutoff timestamp, scans and purges/anonymizes expired records in `customers` and `customer_timeline_events`, records job metrics, issues purge proof receipt (`actionType: 'dpdp.retention.purge'`).
  - `reportBreachIncident`: Formats DPBI reference number (`DPBI-YYYY-XXXXXXXX`), prepares statutory intimation packages for High/Critical breaches, issues Ed25519 receipt (`actionType: 'dpdp.breach.incident_reported'`).
  - `generateDpbiNotificationPackage`: Generates formal intimation document and markdown notification template for affected data principals.
