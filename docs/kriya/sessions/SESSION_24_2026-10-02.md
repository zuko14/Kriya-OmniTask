## 1. Context & Objectives

During WP-7.5 console screen development (documented in `docs/kriya/sessions/SESSION_UI_07_2026-10-02.md`), the parallel UI stream identified 3 critical backend requirements:
1. **Verification Queue API:** `GET /api/v1/verification/jobs?status=pending|mismatch|expired` (tenant-scoped, paginated) to unblock the final WP-7.5 screen (`VerificationQueue.tsx`).
2. **Paginated Proof Receipts API:** `GET /api/v1/proof/receipts` to support efficient pagination instead of loading the full `/proof/export` bundle.
3. **Audit Item S55 (P1 Integrity Defect):** In `outcomeInstrumentationService.ts`, per-workflow metrics had fallback logic:
   - `outcomesCount: stats.verified || stats.runs` counted unverified runs as outcomes when zero were verified.
   - `costPerOutcomeUsd` fell back to cost per run.
   - `verifiedActionRate: (verified || runs) / runs` reported 100% when 0 actions were verified.
   - `byModel.avgLatencyMs` returned 0 ms (rather than `null`) with 0 calls.
   - Unknown cascade levels defaulted into `L0_rule`.

All 3 items were prioritized and resolved to complete production quality.

## 2. Changes Implemented

### A. S55 Fix (Outcome Instrumentation Honesty)
- In [`src/outcomes/service/outcomeInstrumentationService.ts`](file:///c:/Users/chait/OneDrive/Desktop/SYSTEMS_ALL/kriyaAI_omnitask/src/outcomes/service/outcomeInstrumentationService.ts):
  - `byWorkflow.outcomesCount`: strictly set to `stats.verified` (no fallback to `stats.runs`).
  - `byWorkflow.costPerOutcomeUsd`: returns `Math.round((stats.cost / stats.verified) * 1000) / 1000` when `stats.verified > 0`, otherwise `null` (never cost per run).
  - `byWorkflow.verifiedActionRate`: returns `Math.round((stats.verified / stats.runs) * 1000) / 10` when `stats.runs > 0`, otherwise `null`. Zero verified actions with runs now correctly reports `0%`, never 100%.
  - `byModel.avgLatencyMs`: returns `Math.round(stats.latencySum / stats.calls)` when `stats.calls > 0 && stats.latencySum > 0`, otherwise `null` (never 0 ms).
  - `calculateCascadeMix`: filters unknown cascade levels, counting only recognized levels so unmodeled levels never pollute or inflate `L0_rule`.
- In [`src/outcomes/types/outcomeKpiTypes.ts`](file:///c:/Users/chait/OneDrive/Desktop/SYSTEMS_ALL/kriyaAI_omnitask/src/outcomes/types/outcomeKpiTypes.ts):
  - Updated `CostPerOutcomeReport.byModel.avgLatencyMs` type to `number | null`.
