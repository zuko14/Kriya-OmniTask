# Session 13 — 2026-10-02

## Goal
Implement WP-2.5: Human gate (interrupt/resume) <-> Attention Center (Milestone M2 / Milestone M4 integration).
Scope:
1. Durable park at `human_gate` node in `GraphExecutor`: saves run state with status `'parked'`, records park reason, and idempotently issues an Attention item via `AttentionService.escalateOnce()`.
2. Structured Attention Item payload: assigns role (`finance_manager`, `admin`, etc.), captures `runId`, `nodeId`, `graphId`, `requiredRole`, `financialValueUsd`, `customerId`, and full state in `context_data_json`.
3. Bi-directional workflow resumption & attention synchronization:
   - When an operator approves or rejects via the Workflow Runs API (`POST /api/v1/workflows/runs/:runId/approve` or `reject`), the run resumes from checkpoint and auto-resolves the linked Attention item.
   - When an operator resolves an attention item via Attention Center (`POST /api/v1/attention/items/:id/resolve`), the linked parked workflow run automatically resumes from its checkpoint.
4. Edge condition routing: normalizes approval input so that `approval.decision`, `decision`, and boolean `approved`/`rejected` evaluate simultaneously across DAG branch edges.
5. Timeout policy: `GraphExecutor.evaluateParkedRunTimeout(runId, now)` evaluates `timeoutMs` and executes `timeoutAction` (`reject`, `auto_approve`, or `escalate`), updating the linked Attention item and driving the run accordingly.
6. Multi-tenant isolation: enforces strict tenant isolation across both Graph Runs and Attention Items.

## Decisions made (D13 decided)
- **D13 (Decided):** Human Gate Interrupt/Resume and Attention Center Bi-Directional Synchronization (WP-2.5, Milestone M2/M4). A workflow run parking at a `human_gate` node idempotently provisions an Attention item using `correlationId = `${runId}:${node.id}`` via `AttentionService.escalateOnce()`, capturing complete context (`runId`, `nodeId`, `graphId`, `requiredRole`, `financialValueUsd`, `customerId`, `state`). Resumption is bi-directionally synchronized: resolving the attention item from the Attention Center auto-resumes the parked run from its last durable checkpoint, and approving/rejecting via the Workflow API auto-resolves the attention item. Resumption inputs are normalized across `approval.decision`, `decision`, and booleans (`approved`/`rejected`) so DAG condition evaluators match expected branches deterministically. Configurable timeout policies (`reject`, `auto_approve`, `escalate`) execute when `timeoutMs` expires, maintaining audit integrity.
