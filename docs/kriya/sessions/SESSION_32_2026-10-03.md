## 1. Context & Objectives

Milestone M8 (Production Operations) continues with WP-8.5: **Release, canary, rollback, hosting**.
As Kriya AI transitions from pre-production to multi-tenant production operations, mission-critical agentic operations in regulated Indian enterprises require deterministic canary rollout, automated sub-second emergency rollback, contract version enforcement, and strict data residency governance.

Core objectives for 100% production-level implementation:
1. **Deterministic Canary Routing Engine (`CanaryRoutingEngine`):**
   - Tenant hash-bucket calculation (`SHA-256(tenantId) % 100`) providing 0-99 bucket assignment with guaranteed session affinity.
   - Phased progressive deployment (5% → 10% → 25% → 50% → 100%).
   - Tripwires triggering immediate rollback when error rate >1.0% or P99 latency >1,500ms.
2. **One-Step Instant Rollback Automation (`OneStepRollbackEngine`):**
   - Instantaneous canary traffic retraction to 0% and deployment status lock to `rolled_back`.
   - Idempotent execution for repeated rollback attempts.
   - Non-repudiable Ed25519 cryptographic Proof receipt generation via `ProofService` (`deployment.rollback`).
   - SRE incident escalation to the Human Attention Center via `AttentionService.escalateOnce` (`P1_HIGH`, `slo_burn`).
   - Rollback audit event persistence in `deployment_rollback_events`.
3. **API Versioning & Contract-Locked Gate (`ApiVersionManager`):**
   - Semver comparison logic (`compareSemver`).
   - Contract locking: returns HTTP 426 Upgrade Required if client version is below `minSupportedClientVersion`.
   - RFC 8594 compliance: automatically generates and attaches `Deprecation` and `Sunset` HTTP headers; returns HTTP 410 Gone for sunset APIs.
4. **India Sovereign Hosting & DPDP 2023 Governance (`DataResidencyEngine`):**
   - Strict localization enforcement for `IN_DPDP_2023` jurisdiction: primary region `ap-south-1` (Mumbai) and DR region `ap-south-2` (Hyderabad).
   - Dynamic validation rules blocking unauthorized cross-border data movements and unapproved LLM inference regions.
   - Canonical cloud infrastructure blueprint exported via `/api/v1/deployment/hosting/config` documenting KMS customer-managed key locations, edge CDN ingress PoPs (Mumbai, Delhi, Chennai, Bengaluru), and multi-AZ replication.
5. **Database Migration 057 (`src/storage/migrations/057_release_canary_rollback_and_hosting_schema.sql`):** Creates `api_version_registrations`, `canary_routing_configurations`, `canary_telemetry_snapshots`, `deployment_rollback_events`, and `data_residency_configs`.
6. **Fastify REST APIs (`src/api/routes/deploymentRoutes.ts`):** 11 production endpoints under `/api/v1/deployment/*` protected by JWT authentication and granular RBAC.
7. **Documentation & ADR:** Authored `ADR-032-release-canary-rollback-and-india-hosting.md`.
8. **Verification Evidence:** `tsc --noEmit` and `tsc --noEmit -p web` exiting code 0, 19/19 tests passing in `tests/unit/releaseCanaryRollbackHostingProduction.test.ts`.

## 2. Changes Implemented

### A. Database Migration 057 (`src/storage/migrations/057_release_canary_rollback_and_hosting_schema.sql`)
- Created `api_version_registrations`: tracks registered API versions, status (`active`, `deprecated`, `sunset`), minimum supported client versions, and RFC 8594 sunset timestamps.
- Created `canary_routing_configurations`: tracks deployment canary weights, step size, max error rate threshold, max P99 latency threshold, and current status.
- Created `canary_telemetry_snapshots`: records telemetry windows, total requests, error count, error rate, P95/P99 latency, and evaluation verdicts (`healthy`, `warning`, `critical`).
- Created `deployment_rollback_events`: audit ledger of rollbacks storing previous and target weights, rollback type (`automated_telemetry`, `manual_operator`, `gate_failure`), reason, proof receipt ID, and attention item ID.
- Created `data_residency_configs`: tenant-specific data sovereignty configurations storing jurisdiction, primary/allowed regions, localization flags, cross-border transfer permission, and approved model inference regions.

### B. Canary Routing Engine (`src/deployment/canary/canaryRoutingEngine.ts`)
- Deterministic 0-99 tenant bucketing using `crypto.createHash('sha256')`.
- Session affinity guaranteeing that the same tenant always evaluates to the same bucket across requests.
- Phased advancement recommendations and telemetry threshold evaluation.

### C. One-Step Rollback Automation Engine (`src/deployment/rollback/oneStepRollbackEngine.ts`)
- Zero-delay canary traffic drain to 0% and deployment status lock.
- Safe idempotent execution handling repeated rollback calls.
- Automated Ed25519 cryptographic Proof receipt issuance with tenant context fallback.
- Automated P1 SRE incident escalation to the Human Attention Center under category `slo_burn`.

### D. API Version Manager & Contract-Locked Gate (`src/deployment/versioning/apiVersionManager.ts`)
- Strict semver parsing and comparison.
- Contract enforcement returning HTTP 426 Upgrade Required with actionable error messages.
- RFC 8594 `Deprecation` and `Sunset` headers formatting and validation.

### E. India Data Residency & Sovereign Hosting Governance (`src/deployment/residency/dataResidencyEngine.ts`)
- Verification engine enforcing India DPDP Act 2023 compliance.
- Region restrictions validating primary `ap-south-1` (Mumbai) and secondary `ap-south-2` (Hyderabad).
- Gate rejecting cross-border data egress and unapproved foreign LLM inference endpoints.
- Canonical India cloud hosting configuration blueprint export.

### F. Repository & Service Layer
- `src/deployment/repositories/deploymentRepository.ts`: Implemented relational persistence for API versions, canary configs, telemetry snapshots, rollback events, and data residency.
- `src/deployment/service/deploymentService.ts`: Consolidated high-level orchestration methods for deployments, rollbacks, canary evaluation, version contracts, and residency governance.

### G. REST API Surface (`src/api/routes/deploymentRoutes.ts`)
Exposed 11 new endpoints:
- `POST /api/v1/deployment/releases/:id/rollback/instant`: One-step manual instant rollback.
- `POST /api/v1/deployment/canary/evaluate`: Ingests telemetry and triggers automated emergency rollback if thresholds breached.
- `GET /api/v1/deployment/canary/:id/route-check`: Deterministic route check for a tenant.
- `POST /api/v1/deployment/canary/:id/telemetry`: Records telemetry snapshot.
- `GET /api/v1/deployment/releases/:id/rollback-events`: Lists rollback audit trail.
- `POST /api/v1/deployment/versions`: Registers an API version.
- `GET /api/v1/deployment/versions`: Lists registered API versions.
- `POST /api/v1/deployment/versions/validate-contract`: Validates client version against minimum contract.
- `POST /api/v1/deployment/residency`: Configures tenant data residency.
- `GET /api/v1/deployment/residency`: Retrieves tenant data residency config.
- `POST /api/v1/deployment/residency/validate`: Validates target region/inference compliance.
- `GET /api/v1/deployment/hosting/config`: Public India sovereign hosting blueprint.
