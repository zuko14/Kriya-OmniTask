## Decisions made / needed
- **D21 (Real Embeddings, pgvector & Dual-Mode Vector Retrieval Architecture)**:
  - Real embedding generation utilizes OpenAI-compatible HTTP endpoints (OpenRouter, OpenAI, Gemini) via native `fetch` with jittered exponential backoff on 429/5xx and API key redaction.
  - Deterministic hash embeddings are restricted to offline and hermetic unit test environments; `EmbeddingService` throws `PolicyViolationError` if invoked in production mode without a configured real provider.
  - Token costs are determined strictly without fabrication using versioned records in `src/model/gateway/pricing.ts` ($0.02/1M for `text-embedding-3-small`, $0.13/1M for `text-embedding-3-large`).
  - Migration 049 defines a dual-mode schema: on PostgreSQL, `-- PG:` directives activate `CREATE EXTENSION IF NOT EXISTS vector;`, `embedding_vector vector(1536)`, and HNSW indexing (`vector_cosine_ops`); on SQLite, vector data is stored in `embedding_json` and queried using in-memory cosine ranking.
  - Empirical evaluation proves that dense vector and hybrid RRF retrieval decisively outperform lexical BM25 search on semantic paraphrasing queries (Hybrid: 100% Top-1 accuracy, MRR 1.0 vs BM25: 0% Top-1, MRR 0.0).
