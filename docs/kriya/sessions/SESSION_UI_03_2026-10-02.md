### S44 (P0, fixed) — fabricated verification in the Decision Trace drawer
Previous behaviour: any failed `GET /api/v1/escalation/traces/:id` (500, 403, 404, network) was caught and
replaced by a synthetic trace: status `completed`, "Lead record committed and verified in CRM",
`crm_lead_id: lead_44812`, `status: verified ✓`. Unknown step outcomes defaulted to `succeeded`, missing
token counts to `1200`, missing trust tier to `A`. Now: 404 → "No decision trace is recorded for this task.";
403 → "Access denied"; anything else → "Could not load the decision trace. No trace is shown in its place.";
unknown outcome → escalated; tokens/tier rendered only when present.

### S45 (P1, fixed) — inflated Activity Theatre
Previous: "done today" = real count + 42; every event type not explicitly mapped (`agent.state_changed`,
`approval.required`, `security.event`, `stream.ping`) displayed as "completed" and counted as done, as did
`task.started`; running tasks all showed `3.2s`; with no fleet data a hardcoded hierarchy rendered live at
40-90% load and fed "N working". Now only `task.completed` is completed/done; approval → attention,
security → halt, others informational; elapsed only when reported; placeholder fleet idle at 0 load;
"working" from live agent states only.
