## Headline results (live, cheap model `deepseek/deepseek-v4-flash` via OpenRouter)
- **Live Intake → Scheduling end-to-end:**
  A customer request ("Hi, I want to see Dr. Rao tomorrow at 10 am please. Name: Ravi Kumar") flows:
  `Intake` (language detect → emergency triage → consent → classify → deliver)
  → `Scheduling` (`schedule_find_slots` → verified → `schedule_book` → verified → finish)
  → Appointment recorded in the appointment book with confirmed status
  → Signed Ed25519 proof receipt chain verified
  → Customer receives exact confirmation reply.
  - Measured latency: **17.8 s** (incl. probe certification).
  - Cost: **$0.000474** (agent execution) + **$0.001441** (live model certification).
- **Adversarial & Safety protections verified:**
  - Injected prompt attempting to cancel another customer's appointment: rejected (`No appointment for this customer`), victim record untouched.
  - Injected prompt attempting "book all free slots": rejected by deterministic code-level booking limits (`BOOKING_LIMITS.perResourcePerDay = 1`).
  - Doctor name script tolerance: multi-script queries (e.g. Telugu "డాక్టర్ రావు", Hinglish "doctor rao") normalize or gracefully list all resources with guidance rather than returning a false "nothing free".
  - Double booking impossible: SQLite partial unique index (`ux_appointments_slot`) rejects concurrent collisions at the database level.
  - Reschedule failure compensation: a failed reschedule automatically triggers saga compensation to restore original state, preventing orphaned bookings.

## Decisions made (D8)
- **D8 (ADR-011):** Kriya appointment book is the primary system of record for tenants without external calendar integration. External calendar connectors (WP-5.4) will sit behind the same tool interfaces (`schedule_*`).
- Code-bound tool arguments (`bindPaths`) prevent prompt injection from impersonating other customers.
