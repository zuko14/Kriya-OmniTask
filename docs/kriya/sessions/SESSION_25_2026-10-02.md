## 1. Context & Objectives

Milestone M6 focuses on verifiable outcomes, learning, and automated release safety. Under WP-6.2 (Evals-as-CI), the system requires:
1. **Automated CI Evaluation Harness:** Curated golden test sets per agent running in CI pipelines.
2. **Model-Swap & Charter-Change Gating:** Enforce that a model swap (e.g. OpenRouter DeepSeek $\to$ Gemini $\to$ Claude) or charter change cannot deploy or activate if regression occurs.
3. **Resolution of Audit S24:** The faithfulness grader (`QualityReviewer` / `DriftDetector`) previously used pure lexical bag-of-words token overlap (>3 characters), penalizing valid, polite conversational paraphrasing. Required claim-level checking and entity verification before benchmark scores gate releases.
4. **Resolution of Audit S27:** Single-run model certifications were susceptible to stochastic noise and conflated transient provider/network errors (HTTP 429, 500, timeouts) with cognitive reasoning failures. Required $k$-trial pass$^k$ consistency and error categorization.
5. **Database Auditability & Interfaces:** Migration 052 for persistent CI gating runs, CLI runner (`npm run evals:ci`), and Fastify REST endpoints (`/api/v1/evaluation/ci/*`).

### D. CI Evaluation Engine & Regression Gate (`src/evaluation/ci/service/evalsAsCiService.ts`)
- Implemented `EvalsAsCiService`:
  - `evaluateCase`: Runs test case across $k$ trials, measuring latency/cost and verifying route, tools, zero retention, and state assertions.
  - `evaluateAgentSuite`: Computes pass rate and critical safety breaches.
  - `evaluateModelSwap`: Enforces model swap gating rules:
    - Rule 1: Zero Critical Safety Breaches (any failure on emergency or adversarial test immediately blocks swap).
    - Rule 2: Non-regression on overall pass rate (cannot drop below baseline by $>1\%$).
    - Rule 3: Autonomy & tool fidelity (forbidden tools block release).
    - Rule 4: Approves only on parity or improvement.
  - `evaluateCharterUpdate`: Evaluates proposed charter vs baseline charter, blocking deployment if capabilities or emergency handling regress.
  - `runCiPipeline`: Runs all registered suites and returns overall verdict with exitCode (`0` for pass, `1` for fail).
