## 1. Context & Objectives

Milestone M6 focuses on verifiable outcomes, learning, and automated operational safety. Under WP-6.3 (Error-budget autonomy throttling), the system requires:
1. **Mathematical Rolling Error Budgets:** Derived from outcome metrics and SLA targets per risk tier ($T_0=100\%$, $T_1=95.0\%$, $T_2=99.0\%$, $T_3=99.9\%$).
2. **S53 Honesty Mandate:** Zero-fabrication honest unmeasured baselines (when sample count is 0, report `unmeasured: true`, `verifiedActionRate: null`, never fake perfection).
3. **Automated Step-Down Throttling:** When an agent's error budget is exhausted ($\ge 100\%$ burned), its autonomy steps down automatically ($T_3 \to T_2 \to T_1 \to T_0$).
4. **Immediate Tripwires:** When consecutive read-back verification failures or critical errors occur ($\ge 2$), immediate tripwire throttling activates regardless of total sample size.
5. **Attention Center Escalation:** Immediate `P1_HIGH` priority exception filed under category `policy_violation`, deterministically routed to the agent's charter owner (`billing_manager`, `clinic_manager`, `records_lead`).
6. **Runtime Graph Enforcement:** When throttled (e.g. from $T_2$ to $T_1$), any tool above the effective cap gets `requireApproval: true`. In `agentLoop.ts`, the execution halts and parks at `human_gate`, refusing autonomous execution under Mandate.
7. **Human-in-the-Loop Restoration Governance:** Autonomy NEVER self-restores on live traffic. Restoration requires human review with valid justification, with optional pre-restoration golden eval suite execution (`verifyFirst: true`).
8. **Storage Schema & REST Endpoints:** Database migration 053 (`agent_error_budgets`, `agent_autonomy_events`) and REST endpoints under `/api/v1/autonomy/*`.

## 2. Changes Implemented

### A. Database Migration 053 (`src/storage/migrations/053_error_budget_autonomy_throttling_schema.sql`)
- Created table `agent_error_budgets`:
  - Per-tenant, per-agent tracking of configured tier cap, effective tier cap, throttling status, SLA targets, error budgets, sample counts, failure counts, consecutive failures, and throttled/restored timestamps and actors.
- Created table `agent_autonomy_events`:
  - Append-only immutable audit trail capturing every state change (`throttled`, `budget_warning`, `restored`) with evidence JSON.

### B. Types & Contracts (`src/throttling/types/autonomyThrottlingTypes.ts`)
- Defined `TIER_SLA_CONFIG` with risk tier targets ($T_0=100\%$, $T_1=95\%$, $T_2=99\%$, $T_3=99.9\%$) and corresponding error budgets.
- Defined `DEFAULT_ERROR_BUDGET_CONFIG` (window: 24h, min sample size: 3, burn throttle: 100%, warning burn: 75%, tripwire threshold: 2).
- Defined request validation schemas `EvaluateAutonomyRequestSchema` and `RestoreAutonomyRequestSchema` (enforcing $\ge 5$ character human justification reasons).
- Defined input types `RestoreAutonomyInput` and `EvaluateAutonomyRequest`.

### C. Repository Layer (`src/throttling/repositories/autonomyThrottlingRepository.ts`)
- Implemented `AutonomyThrottlingRepository`:
  - `getBudget`, `listBudgets` (with optional `onlyThrottled` filter).
  - `upsertBudget`: Atomic update-or-insert maintaining state and timestamps.
  - `recordEvent`: Append-only audit logger for autonomy events.
  - `listEvents`: Paginated, filtered event retrieval.

### D. Service Engine (`src/throttling/service/autonomyThrottlingService.ts`)
- Implemented `AutonomyThrottlingService`:
  - `getEffectiveTierCap`: Fast path resolving throttled effective tier cap for runtime execution.
  - `evaluateAgent`: Evaluates proof receipts, verification jobs, and tool calls over the rolling window. Checks S53 unmeasured status, calculates burn rate, triggers automated step-down ($T_3 \to T_2 \to T_1 \to T_0$) on burnout or tripwire breach, logs warning on $\ge 75\%$ burn, files `P1_HIGH` Attention Center item deterministically routed to `charter.owner`, and records audit event.
  - `evaluateFleet`: Batch evaluation across tenant workforce.
  - `restoreAutonomy`: Enforces human-in-the-loop governance. Rejects trivial justifications; runs golden eval suite when `verifyFirst: true` is requested; updates budget record and logs audited event.
  - `recordDirectExecutionFailure`: Direct tripwire incrementing consecutive failure count and immediately evaluating throttling.
