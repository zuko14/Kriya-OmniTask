## Decisions made / needed
- **D22 (Kriya Reach Browser Automation Architecture)**:
  - Browser automation operates under strict domain allowlists (exact or `*.domain.com` wildcards) and action allowlists. Any attempt to navigate outside allowlisted domains or to private/loopback/cloud-metadata IPs (`169.254.169.254`) throws `ReachSecurityViolationError`.
  - Non-HTTP protocols (`file:`, `javascript:`, `data:`, `chrome:`) are strictly forbidden.
  - Per-run session isolation is enforced: each session uses an ephemeral, incognito context with zero state or cookie carry-over to subsequent runs.
  - Consequential browser actions capture PNG screenshot evidence with SHA-256 hash attribution. Every completed session issues a cryptographically signed Ed25519 `ProofReceipt` via `ProofService` that can be verified offline.
  - Multi-tiered emergency kill switch allows global platform-wide, tenant-scoped, or active in-flight session termination via `AbortController`.
  - Production driver uses Playwright in an isolated process; hermetic mock driver provides zero-dependency offline unit testing.
