# Session 12 — 2026-10-02

## Goal
Implement WP-5.1: Production Database: PostgreSQL Migration Harness & Row Locks (Milestone M5).
Scope:
1. Dual-mode database architecture (`DB_DRIVER='postgres' | 'sqlite'`).
2. Enterprise PostgreSQL production driver using `pg.Pool`, statement timeouts (30s), idle timeouts (30s), and connection timeouts (5s).
3. Parameter translation (`toPostgresSql`): converts unquoted `?` into `$1, $2, ...` while preserving `?` inside single quotes, double quotes, and escaped quotes (`''`).
4. Migration DDL dialect translation (`translateDdlForPostgres`): converts SQLite idioms (`INTEGER PRIMARY KEY AUTOINCREMENT` -> `SERIAL PRIMARY KEY`, `datetime('now')` -> `CURRENT_TIMESTAMP`).
5. Transaction savepoints: supports nested transactions via `SAVEPOINT`, `RELEASE SAVEPOINT`, and `ROLLBACK TO SAVEPOINT`.
6. Concurrency row locks: `SELECT ... FOR UPDATE` row locks added to `MandateService` (`mandate_usage`), `AppointmentBook` (`appointments` in `reschedule`, `cancel`, `restore`), and `RefundRepository` (`payment_refunds` in `voidRefund`).
7. SQLite client row-lock sanitization: automatically strips `FOR UPDATE` clauses at runtime so the exact same row-locked queries execute cleanly on in-memory SQLite in test environments.
8. Preservation of S5 honesty guard: throws `DatabaseError` refusing silent fallback to in-memory SQLite when `DB_DRIVER=postgres` and `DATABASE_URL` is unset or `:memory:`.

## Decisions made (D12 decided)
- **D12 (Decided):** Dual-mode PostgreSQL production database adapter and row-lock concurrency (WP-5.1, Milestone M5). The system provides dual-mode database operation: production environments run against PostgreSQL with connection pooling (`pg.Pool`), statement timeouts, parameter translation (`?` -> `$1, $2...`), and nested transaction savepoints; test/sandbox environments run against in-memory SQLite (`node:sqlite`). Concurrency protection uses row-level locking (`SELECT ... FOR UPDATE`) in business-critical paths (`MandateService.authorize`, `AppointmentBook.reschedule/cancel/restore`, `RefundRepository.voidRefund`). The SQLite client runtime sanitizes `FOR UPDATE` clauses automatically, allowing identical code to execute across both engines. S5 honesty guard is enforced: configuring `DB_DRIVER=postgres` without a valid PostgreSQL connection URL fails fast with a explicit refusal to fall back to in-memory SQLite.
