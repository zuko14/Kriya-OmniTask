## 1. Context & Objectives

Milestone M8 (Production Operations) continues with WP-8.3: **Observability + SLOs**.
Enterprise production deployments require standardized real-time telemetry compatible with Prometheus and Grafana, distributed request correlation conforming to W3C Trace Context recommendations, and automated Service Level Objective (SLO) error budget governance to protect customer SLAs and reliability targets.

Core objectives for 100% production-level implementation:
1. **Zero-Dependency Prometheus Metrics Registry (`src/observability/metrics/prometheusRegistry.ts`):** High-performance in-memory registry supporting `Counter`, `Gauge`, and `Histogram` (with standard exponential buckets) serializing strictly to the official Prometheus text exposition format (`text/plain; version=0.0.4; charset=utf-8`).
2. **Platform Indicators Catalog (`src/observability/metrics/platformMetrics.ts`):** Pre-registered indicators for HTTP request traffic, workflow steps, LLM token consumption, connector tool invocations, active durable queue sizes, database latencies, and real-time SRE burn rate gauges.
3. **W3C Distributed Tracing Engine (`src/observability/tracing/distributedContext.ts`):** Parser and serializer for W3C `traceparent` (version-traceid-parentid-flags) and `tracestate` vendor pairs with `AsyncLocalStorage` context propagation across asynchronous task chains.
4. **Fastify Server Request Tracing & Metric Hooks (`src/api/server.ts`):** `onRequest` hook extracts incoming W3C trace headers or mints fresh context, echoing headers back in `reply`; `onResponse` calculates latency and records HTTP metrics in `PlatformMetrics.httpRequestsTotal` and `PlatformMetrics.httpRequestDurationSeconds`.
5. **Autonomous Multi-Window SLO Burn Rate Alert Engine (`src/observability/slo/sloEvaluationEngine.ts`):** Computes short (1h 14.4x), medium (6h 6.0x), and long (24h 3.0x) burn rates; dynamically updates Prometheus gauges; dispatches structured alerts (`sre_alerts` and `slo_alert_incidents`); and auto-escalates critical budget burns (14.4x) directly to the Human Attention Center (`reasonCategory: 'slo_burn'`).
6. **Database Migration 055 (`src/storage/migrations/055_observability_prometheus_and_slo_schema.sql`):** Created `slo_alert_incidents` and `prometheus_metric_snapshots`, and updated `013_human_attention_schema.sql` to natively accept `slo_burn`.
7. **REST Endpoints:** Public/scraper `/metrics`, authenticated `/api/v1/observability/metrics/prometheus`, `/slos`, `/alerts`, and `/spans`.
8. **Documentation & ADR:** Authored `SLO_AND_OBSERVABILITY_MANUAL.md` and `ADR-030-observability-slos-and-prometheus-engine.md`.

## 2. Changes Implemented

### A. Prometheus Metrics Registry (`src/observability/metrics/prometheusRegistry.ts`)
- Created `Counter`: strictly monotonically increasing values (`inc(labels?, value = 1)`), prevents negative increments, multidimensional label serialization with proper escaping (`"`, `\`, `\n`).
- Created `Gauge`: arbitrary value setting (`set`, `inc`, `dec`), supporting positive, negative, and zero values.
- Created `Histogram`: tracks values across customized or default exponential buckets (`[0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 0.5, 1, 2.5, 5, 10]`), generating `_bucket{le="..."}`, `_bucket{le="+Inf"}`, `_sum`, and `_count`.
- Created `PrometheusRegistry`: thread-safe in-memory registry producing `# HELP` and `# TYPE` headers, `metrics()` exporter, and `CONTENT_TYPE = 'text/plain; version=0.0.4; charset=utf-8'`.

### B. Platform Metric Catalog (`src/observability/metrics/platformMetrics.ts`)
- Exported global singleton `PlatformMetrics` defining:
  - `http_requests_total` & `http_request_duration_seconds`
  - `agent_executions_total` & `agent_execution_duration_seconds`
  - `model_tokens_total` & `model_call_duration_seconds`
  - `tool_executions_total` & `tool_execution_duration_seconds`
  - `slo_burn_rate_ratio` (windows: `1h`, `6h`, `24h`)
  - `slo_error_budget_remaining_percent`
  - `queue_active_jobs`
  - `db_query_duration_seconds`

### C. W3C Trace Context Distributed Tracing (`src/observability/tracing/distributedContext.ts`)
- Implemented `DistributedContextManager`:
  - `generateTraceId()`: generates 32-hex characters (16 bytes, non-zero).
  - `generateSpanId()`: generates 16-hex characters (8 bytes, non-zero).
  - `parseTraceparent()`: validates 4-part regex, rejects version `ff`, all-zero trace IDs, all-zero parent IDs.
  - `formatTraceparent()`: emits standard `00-${traceId}-${spanId}-${traceFlags}`.
  - `parseTracestate()` / `formatTracestate()`: parses and emits comma-separated vendor key-value pairs.
  - `extractFromHeaders()` / `injectToHeaders()`: extracts or creates trace context and binds to outgoing headers.
  - `AsyncLocalStorage` integration: `run(context, fn)`, `current()`, `createChildContext()`.

### D. Fastify Request & Response Observability Hooks (`src/api/server.ts`)
- `onRequest`: extracts incoming W3C trace context, stamps start time, reflects `x-correlation-id`, `traceparent`, and `tracestate` onto the response.
- `onResponse`: calculates duration in seconds and increments `PlatformMetrics.httpRequestsTotal` and observes `PlatformMetrics.httpRequestDurationSeconds`.

### E. Autonomous Multi-Window SLO Burn Rate Alert Engine (`src/observability/slo/sloEvaluationEngine.ts`)
- Implemented `SloEvaluationEngine`:
  - Evaluates active SLO targets against actual metrics.
  - Computes 1-hour ($14.4\times$ critical), 6-hour ($6.0\times$ high), and 24-hour ($3.0\times$ warning) burn rates.
  - Updates Prometheus gauges `PlatformMetrics.sloBurnRateRatio` and `PlatformMetrics.sloErrorBudgetRemainingPercent`.
  - Dispatches incident alerts via `StructuredAlertDispatcher`.
  - When status is `critical` ($14.4\times$ burn rate or $\le 10\%$ error budget remaining), automatically escalates into the Human Attention Center (`reasonCategory: 'slo_burn'`, priority: `P1_HIGH`), routing to the operations lead.
  - Persists incident records to `slo_alert_incidents` with incident acknowledge and resolve workflow.

### F. Database Migration 055 & Attention Center Integration
- `src/storage/migrations/055_observability_prometheus_and_slo_schema.sql`: defines `slo_alert_incidents` and `prometheus_metric_snapshots` with foreign keys to `tenants` and `slo_definitions`.
- Updated `src/storage/migrations/013_human_attention_schema.sql` to include `'slo_burn'` in `attention_items.reason_category` check constraint.
- Updated `src/attention/types/attentionTypes.ts` and `src/attention/priority/priorityCalculator.ts` to support `'slo_burn'`.

### G. Observability REST API Routes (`src/api/routes/observabilityRoutes.ts`)
- `GET /metrics`: Standard unauthenticated Prometheus text scrape endpoint.
- `GET /api/v1/observability/metrics/prometheus`: Authenticated Prometheus scrape endpoint (`audit:read`).
- `GET /api/v1/observability/slos`: Lists all active SLOs.
- `POST /api/v1/observability/slos`: Creates a new SLO (`system:admin`).
- `POST /api/v1/observability/slos/:id/evaluate`: Evaluates SLO, updates Prometheus gauges, auto-escalates critical alerts (`system:admin`).
- `GET /api/v1/observability/alerts`: Lists alert incidents (`audit:read`).
- `POST /api/v1/observability/alerts/:id/acknowledge`: Acknowledges alert incident (`system:admin`).
- `POST /api/v1/observability/alerts/:id/resolve`: Resolves alert incident (`system:admin`).
- `GET /api/v1/observability/spans`: Searches and filters spans across traces (`audit:read`).
