## 1. Context & Objectives

Milestone M6 (Outcomes & Learning) culminates in WP-6.4: **Governed adaptation**.
The enterprise outer improvement loop (§6, §14, §15, §23 of CLAUDE.md; Blueprint §14, §28) requires an autonomous pipeline for continuous learning that strictly prohibits live-traffic self-modification while ensuring verified, regression-free enhancements.

Core objectives for 100% production-level implementation:
1. **S21 Resolution (Golden Suite Replay Simulation):** Replace mock simulation scoring with a real production replay evaluator that runs candidate proposals against active agent golden suites (`ALL_GOLDEN_SUITES`), enforcing zero regressions across all existing test cases.
2. **Outcome Failure Harvester:** Automatically harvest operational failure signatures from `verification_jobs` (status `mismatch` / `expired`) and `agent_error_budgets` (`is_throttled = 1` or `consecutive_failures >= 2`), clustering them into candidate-ready remediation opportunities.
3. **Strict Candidate Proposal Types:** Enforce typed proposal structures (`new_skill`, `tool_fix`, `policy_tightening`, `retry_timing`) converting fuzzy model judgment into deterministic zero-token logic, while strictly rejecting open-ended `rewrite_agent` prompt overhauls.
4. **Human Approval Gating & Cryptographic Proof Receipts:** Require human operator sign-off with strict role permissions (`platform` scope requires `owner`, `tenant` scope requires `admin`/`owner`). Issue cryptographically signed Ed25519 `ProofReceipt` items on approval and rejection.
5. **Deterministic Session-Bucket Canary Routing:** Implement `AdaptationCanaryRouter` using deterministic session hash-bucketing (`hash(tenantId:sessionId:agentSlug) % 100 < canaryWeightPct`) to ensure deterministic session-sticky canary traffic routing.
6. **Canary Telemetry Evaluation & Automated Emergency Rollback:** Monitor live canary metrics against baseline. If an error spike ($> 5\%$ or $> 2\times$ baseline), escalation breach ($> 10\%$), or latency degradation ($> 2.5\times$) is detected, automatically roll back canary traffic to 0%, file an emergency P1 Attention escalation, and issue a rollback Proof receipt.
7. **Progressive Promotion:** Advance healthy canary deployments through progressive tiers ($10\% \to 50\% \to 100\%$), issuing a promotion Proof receipt upon 100% rollout.
8. **REST API Routes:** Provide Fastify routes under `/api/v1/adaptation/*` with authentication and RBAC.

## 2. Changes Implemented

### A. Production Replay Evaluator Resolving S21 (`src/adaptation/services/adaptationSimulationEngine.ts`)
- Implemented `createProductionReplayEvaluator(ciService)` and `getGoldenSuiteForAgent(agentSlug)`:
  - Connects proposals directly to `ALL_GOLDEN_SUITES` and `EvalsAsCiService`.
  - Evaluates candidate modifications across all golden test cases of the target agent (32 cases for Intake, 30 for Scheduling, 7 for Payments, etc.).
  - Simulates a reproduction case for the target failure signature.
  - Enforces the **Zero Golden Regressions Policy**: If even 1 existing golden case fails, `goldenSuiteRegressions > 0`, `simulationStatus = 'regressed'`, and approval is blocked.
  - S21 is formally marked **FIXED**.

### B. Outcome Failure Harvester (`src/adaptation/services/failureHarvestingService.ts`)
- Created `FailureHarvestingService`:
  - `harvestFromOutcomes(tenantId, options)`: Queries SQLite/Postgres for operational failures.
  - Queries `verification_jobs` where `status IN ('mismatch', 'expired')` within the rolling window. Maps tools to agent slugs (`scheduling`, `payments`, `document`, `attention`, `intake`) and ingests `tool_failure` signatures.
  - Queries `agent_error_budgets` where `is_throttled = 1` or `consecutive_failures >= 2`. Ingests `model_failure` signatures with effective and configured tier metadata.
  - Clustered deterministically by `FailureClusteringService` (`failureClass::agentSlug::rootCause`), flagging clusters as `candidateReady` when total occurrences reach threshold.

### C. Deterministic Session-Bucket Canary Router (`src/adaptation/canary/adaptationCanaryRouter.ts`)
- Created `AdaptationCanaryRouter`:
  - `shouldRouteToCanary(tenantId, agentSlug, sessionId)`:
    $$\text{bucket} = \text{hashSha256}(tenantId + ':' + sessionId + ':' + agentSlug) \pmod{100}$$
  - Evaluates active approved canary evaluations. If `bucket < canaryWeightPct`, returns `routeToCanary = true` with candidate version tag.
  - Promoted versions ($100\%$) always route to the promoted version; rolled-back versions ($0\%$) route to baseline.

### D. Governed Adaptation Service Upgrade (`src/adaptation/services/governedAdaptationService.ts`)
- Integrated default `createProductionReplayEvaluator()` into the simulation engine.
- Integrated `ProofService` to issue cryptographically signed Ed25519 `ProofReceipt` records on:
  - Proposal approval (`adaptation.proposal_approved`).
  - Proposal rejection (`adaptation.proposal_rejected`).
  - Automated canary rollback (`adaptation.canary_rolled_back`).
  - Canary promotion (`adaptation.canary_promoted`).
- Integrated `AttentionService` to trigger immediate `P1_HIGH` Attention Center escalations under category `policy_violation` upon automated canary rollback.
- Added `rejectProposal(proposalId, reason, rejectedBy)` enforcing human justification.
- Added `harvestFromOutcomes(tenantId, options)` delegating to `FailureHarvestingService`.

### E. Domain Types & Barrel Export (`src/adaptation/types/adaptationTypes.ts`, `src/adaptation/index.ts`)
