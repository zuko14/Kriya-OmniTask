# Kriya AI — DPDP Data Breach Notification Operational Runbook

## 1. Statutory Authority & Trigger Conditions

Under **Section 8(6) of the Digital Personal Data Protection Act, 2023 (DPDP Act 2023)**:
> *"In the event of a personal data breach, the Data Fiduciary shall give the Board [Data Protection Board of India] and each affected Data Principal, intimation of such breach in such form and manner as may be prescribed."*

This runbook defines the mandatory incident triage, statutory notification protocol, technical containment workflow, and template notices required when a personal data breach is detected within the Kriya AI platform.

---

## 2. Severity Classification Matrix

| Severity | Incident Characteristics | Statutory Action Required | Target Notification Timeline |
| :--- | :--- | :--- | :--- |
| **CRITICAL** | Mass PII exfiltration, unencrypted DB backup compromise, credential leakage affecting >1,000 principals, or active extortion/ransomware. | Immediate DPBI intimation + Emergency Data Principal alert + Platform lock. | **Within 6 hours** of confirmation |
| **HIGH** | Unauthorized access to customer profiles/records, unintended third-party data disclosure affecting 100–1,000 principals. | Formal DPBI notification + Targeted Data Principal notification + Forensic audit. | **Within 24 hours** |
| **MEDIUM** | Accidental isolated exposure contained within 1 hour, localized API misconfiguration affecting <100 principals with no data exfiltration detected. | DPBI intimation package prepared + DPO assessment on principal harm risk. | **Within 48 hours** |
| **LOW** | Minor internal authorization defect detected and patched with zero exfiltration or external access verified via audit logs. | Internal incident logging + Remediation patch. Recorded in quarterly compliance review. | No external notice unless risk escalates |

## 3. Incident Response Protocol: Step-by-Step

```
[Detection / Alert] ──> [Triage & Containment (<1h)] ──> [Forensic Analysis (<4h)]
                                                                  │
                                                                  ▼
[Board Closure (<72h)] <── [Principal Notice (<24h)] <── [DPBI Intimation (<6h)]
```

### Phase 1: Detection & Triage (T0 to T0 + 1 Hour)
1. **Trigger:** Alert raised by SIEM, anomaly detection, IDS/IPS, employee report, or external bug bounty report.
2. **On-Call Security Engineer:**
   - Immediately declares a Security Incident in the incident management system.
   - Pagers the **Incident Commander (IC)** and the **Data Protection Officer (DPO)**.
   - Restricts affected API keys, tokens, and active sessions.

### Phase 2: Containment & Forensic Analysis (T0 + 1 Hour to T0 + 4 Hours)
1. **Isolate Affected Systems:** Sever compromised connections or place affected tenant in maintenance mode.
2. **Collect Evidence:** Preserve logs, memory dumps, and database audit logs (`security_audit_events`, `customer_timelines`).
3. **Determine Scope:**
   - Total number of affected Data Principals.
   - Categories of personal data involved (e.g., names, phone numbers, email addresses, financial info, conversation history).
   - Root cause (e.g., credential leakage, unauthorized access, software vulnerability).

### Phase 3: DPBI Statutory Intimation (T0 + 4 Hours to T0 + 6 Hours)
1. **Execute DPDP Service Command:**
   Call the DPDP Breach Engine API (`POST /api/v1/dpdp/breach/report`) or invoke `DpdpService.reportBreachIncident()`:
   ```json
   {
     "incidentName": "Unauthorized Database Access Incident",
     "severity": "CRITICAL",
     "breachType": "unauthorized_access",
     "affectedPrincipalsCount": 2450,
     "incidentSummary": "Anomalous external IP accessed legacy customer staging replica via leaked service token.",
     "rootCause": "Compromised third-party developer credential rotated immediately upon detection.",
     "remediationSteps": "All tokens invalidated, network IP whitelist enforced, database relocated to isolated VPC subnet.",
     "dpoContact": "dpo@kriya.ai"
   }
   ```
2. **Obtain Reference Identifier:** Capture generated reference ID (e.g. `DPBI-2026-A1B2C3D4`).
3. **Dispatch to DPBI:** The DPO submits the formal intimation package generated by `DpdpService.generateDpbiNotificationPackage()` via the statutory DPBI portal or certified email.

### Phase 4: Data Principal Notification (T0 + 6 Hours to T0 + 24 Hours)
1. Dispatch personalized notification messages (via Email / WhatsApp) to all affected Data Principals using the statutory template generated by `DpdpService`.
2. Ensure communications are available in English and appropriate Eighth Schedule languages (Hindi, Telugu, Tamil, etc.).
3. Record dispatch timestamp in the system via `POST /api/v1/dpdp/breach/:id/mark-principals-notified`.

### Phase 5: Post-Incident Remediation & Board Reporting (T0 + 24 Hours to T0 + 72 Hours)
1. Conduct root-cause analysis (RCA) and implement permanent architectural controls.
2. Complete full cryptographic proof verification of affected data sets.
3. Submit final resolution report to DPBI and archive case file in the compliance repository.

## 4. Statutory Notification Templates

### 4.1 Notice to the Data Protection Board of India (DPBI)
```markdown
To: The Data Protection Board of India
Subject: Statutory Intimation of Personal Data Breach under Section 8(6) of DPDP Act 2023
Reference: [DPBI-REFERENCE-NUMBER]
Date: [DATE]

1. Details of Data Fiduciary:
   - Organization: Kriya AI (Omnitask Technologies Pvt. Ltd.)
   - Data Protection Officer: [DPO Name], Email: dpo@kriya.ai, Phone: +91-XXXX-XXXXXX

2. Description of the Personal Data Breach:
   - Nature & Category of Incident: [Unauthorized Access / Accidental Exposure]
   - Approximate Number of Data Principals Affected: [COUNT]
   - Categories of Personal Data Compromised: [e.g. Name, Phone, Email, Interaction Records]
   - Suspected Date and Time of Incident: [TIMESTAMP]

3. Likely Consequences:
   - Risk assessment on affected Data Principals and probability of unauthorized utilization.

4. Mitigation & Remedial Measures Implemented:
   - Technical containment actions taken immediately.
   - Corrective actions to prevent future occurrence.

5. Intimation to Data Principals:
   - Schedule and communication channels deployed to notify affected Data Principals.
```

### 4.2 Notice to Affected Data Principals
```markdown
Subject: Important Security Notice Regarding Your Personal Data [Ref: DPBI-REFERENCE-NUMBER]

Dear [Customer Name],

We are writing to inform you of a personal data security incident that may have affected your personal information, in compliance with Section 8(6) of the Digital Personal Data Protection Act, 2023.

What Happened:
On [Date], our automated monitoring systems identified unauthorized access affecting certain customer profile information.

What Information Was Involved:
The affected data was limited to [Name, Contact Phone, and Preferred Channel]. No passwords, payment details, or government IDs were accessed.

What We Have Done:
Our security response team immediately contained the incident, revoked all associated credentials, and deployed enhanced security controls.

What You Should Do:
We recommend remaining vigilant against unsolicited communications or phishing attempts referencing your contact details.

Contact Us:
For any questions or to exercise your rights under Section 13 (Right of Grievance Redressal), please contact our Data Protection Officer at dpo@kriya.ai.
```
